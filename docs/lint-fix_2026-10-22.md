# lintエラー修正の記録（2026-10-22）

`react-hooks/set-state-in-effect`（effect 内での同期的な setState）などの指摘を解消した記録。
**挙動は変えていない。** 差分の全文は [`lint-fix_2026-10-22.diff`](./lint-fix_2026-10-22.diff)（package-lock.json を除く）。

## 背景

`eslint-plugin-react-hooks` v7 のルールで、effect の中から `setLoading(true)` などを
同期的に呼ぶ書き方が指摘される（余計な再描画が起きるため）。
修正前は エラー5件・warning2件、修正後は **0件**。

## 修正の方針

取得処理を「state に触れない関数」と「結果を state に反映する処理」に分け、
effect の中では **非同期の結果が返ってから** state を更新する。

| ファイル | 修正内容 |
|---|---|
| `frontend/src/App.tsx` | トークンがない場合の `setLoading(false)` を effect から削除。`loading` の初期値を「トークンの有無」で決める |
| `frontend/src/pages/Admin.tsx` | 取得を `loadAdminData()` に分離。初回は effect 内で `.then` に反映。期の切り替えなどの再取得は従来どおり `fetchAll()` |
| `frontend/src/pages/Dashboard.tsx` | 取得を `loadDashboard()` に分離。初回は effect 内で `.then` に反映。再取得は従来どおり `fetchData()` |
| `frontend/src/pages/Schedule.tsx` | 取得を `loadSchedule()` に分離（新メンバー / メンターで分岐）。反映は `applySchedule()` |
| `frontend/src/pages/Training.tsx` | 初回の取得を effect 内で `.then` に反映。`fetchData()` は他の操作用にそのまま残す |
| `frontend/eslint.config.mjs`（新規） | react-hooks v7 と `no-explicit-any` を有効にした lint 設定 |
| `frontend/package.json` | eslint・typescript-eslint・eslint-plugin-react-hooks を devDependencies に追加 |
