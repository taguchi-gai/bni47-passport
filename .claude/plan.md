# トレーニング受講管理機能 実装プラン

決定日: 2026-09-16

## 背景・要件

パスポートプログラムとは別に、BNIのトレーニング受講状況を管理したい。

トレーニング種類（9種）:
| 表示順 | 名称 | 推奨期限 |
|---|---|---|
| 1 | MSP2.0 | 30日以内 |
| 2 | アクセラレーター | 90日以内 |
| 3 | ウィークリープレゼン | なし |
| 4 | 1to1 | なし |
| 5 | リファーラル | なし |
| 6 | メインプレゼン | なし |
| 7 | チャプターディベロップメント | なし |
| 8 | ネットワーキングスキル | なし |
| 9 | MSアドオン | なし |

## 決定事項

### 期限の起算日
- **入会後、最初の定例会に参加した日**を起算日とする
- システムでは自動取得できないため、**メンターまたは管理者が手入力**する
- `new_members.first_meeting_date` として保持
- 未入力の場合は期限判定を行わない（警告は出さない）

### 権限
| ロール | 閲覧 | チェック操作 | 初回定例会日の入力 |
|---|---|---|---|
| 新メンバー | 自分の分のみ | 自分の分のみ | 不可 |
| メンター | 全員分 | 全員分（担当プログラム問わず） | 可 |
| 管理者 | 全員分 | 全員分 | 可 |

## データモデル

### 新規テーブル `trainings`（マスター）
- `id`, `name`, `display_order`, `recommended_days`(nullable), `is_active`
- プログラムと同様にマスター管理し、将来の名称変更・追加に対応

### 新規テーブル `training_records`（受講記録）
- `id`, `new_member_id`, `training_id`, `is_completed`, `completed_at`, `completed_by_user_id`, `created_at`
- `(new_member_id, training_id)` でユニーク
- 「誰がチェックしたか」も記録（本人チェックかメンターチェックかの区別用）

### 既存テーブル変更 `new_members`
- `first_meeting_date`（DateTime, nullable）を追加 → **ALTER TABLE のマイグレーション必要**

## API 設計

| メソッド | パス | 権限 | 用途 |
|---|---|---|---|
| GET | `/api/trainings/` | 全ロール | トレーニングマスター一覧 |
| GET | `/api/trainings/records` | 全ロール | 受講状況（新メンバーは自分のみ／他は全員分） |
| PATCH | `/api/trainings/records/{new_member_id}/{training_id}` | 全ロール（本人 or メンター以上） | チェックのON/OFFトグル |
| PUT | `/api/trainings/members/{new_member_id}/first-meeting-date` | メンター以上 | 初回定例会日の設定 |

## フロントエンド

- サイドバーに「**トレーニング**」メニューを追加（全ロール表示）
- `frontend/src/pages/Training.tsx` を新規作成
  - **新メンバー**: 自分の9種チェックリスト（カード形式）、期限表示、自分でチェック可能
  - **メンター・管理者**: 「メンバー × トレーニング」のマトリクス表、初回定例会日の入力欄、全員分チェック可能
- 期限超過の表示: MSP2.0（30日）・アクセラレーター（90日）が未完了かつ期限超過の場合は赤色で警告、期限が近い場合（残7日以内）は黄色

## 作業手順

1. `models.py` にテーブル追加 + `NewMember.first_meeting_date` 追加
2. `backend/routers/trainings.py` 新規作成、`main.py` に登録
3. トレーニングマスターの初期投入（`seed.py` に追加 + 起動時の自動投入）
4. 本番DB用マイグレーション（`first_meeting_date` の ALTER TABLE）
5. フロントエンド `Training.tsx` + サイドバー + `App.tsx` ルーティング
6. ビルド・デプロイ（Firebase Hosting / Render）
7. 本番動作確認

## 備考

- パスポートプログラム（面談予約）とは完全に独立した機能。予約・カレンダー・メール通知とは連動しない
- トレーニング完了時のメール通知は今回は実装しない（必要になれば後から追加）
